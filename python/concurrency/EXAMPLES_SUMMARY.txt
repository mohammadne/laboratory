⏱️ PERFORMANCE INSIGHTS:

I/O-Bound (network, files, databases):
  - Sequential:     ~2.5s for 5 tasks × 0.5s
  - Threading:      ~0.5s ✓ (5x faster)
  - Asyncio:        ~0.5s ✓ (5x faster)

CPU-Bound (math, data processing):
  - Sequential:     ~1.5s for 4 large calculations
  - Threading:      ~1.3s (GIL prevents speedup)
  - Multiprocessing: ~0.5s ✓ (3x faster, true parallelism)

🎯 DECISION GUIDE:

Are you doing I/O-bound work?
  └─ YES → Use asyncio or ThreadPoolExecutor
     └─ Need modern async/await? → asyncio
     └─ Keep it simple? → ThreadPoolExecutor

Are you doing CPU-bound work?
  └─ YES → Use ProcessPoolExecutor or multiprocessing
     └─ Performance critical? → ProcessPoolExecutor
     └─ Need fine control? → multiprocessing.Process

📖 KEY CONCEPTS:

GIL (Global Interpreter Lock):
  - Prevents threads from executing bytecode simultaneously
  - I/O operations release the GIL (threading works for I/O)
  - Multiprocessing bypasses GIL (works for CPU tasks)

Asyncio:
  - Single-threaded event loop
  - Lightweight async/await syntax
  - Best for many I/O operations

Threading:
  - OS-level threads
  - Good for simple I/O tasks
  - Subject to GIL for CPU-bound work

Multiprocessing:
  - Separate Python processes
  - True parallelism (no GIL)
  - Best for CPU-intensive work
